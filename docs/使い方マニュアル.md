# 飲み会管理Bot 使い方マニュアル

このドキュメントは、サーバーメンバー・幹事・運営の方向けに、Botの実際の使い方をまとめたものです。
コマンドの詳細な仕様は [コマンド一覧.md](コマンド一覧.md)、内部設計は [仕様書.md](仕様書.md) を参照してください。

---

## 1. このBotでできること

飲み会(オフ会)ごとに専用のチャンネル・ロールを自動で作り、以下を一元管理します。

- イベント(飲み会)の作成・編集・終了処理
- 参加者の募集・出欠管理(参加ボタンで簡単に参加/キャンセル)
- 飲み会(お店)ごとの記録(1軒目、2軒目…)
- 会費の受領記録(誰からいくら受け取ったか)
- Webブラウザからの参加履歴・会計確認(Webコンソール)

登場する役割は3種類です。

| 役割 | 説明 |
| --- | --- |
| **参加者** | サーバーメンバー全員。イベントを作成したり、参加ボタンで参加できる |
| **幹事** | イベントの作成者。そのイベントの編集・お店登録・会計管理を行う |
| **運営** | サーバー管理者。全イベントの管理・設定変更・削除ができる |

---

## 2. 導入時の初期設定(運営向け)

Botをサーバーに招待した直後は設定が空のため、`/event create` などは実行できません。
運営ロールを持つ人が、最初に以下の5項目を設定してください。

```
/settings set key:event-category channel:(イベント用カテゴリ)
/settings set key:archive-category channel:(アーカイブ用カテゴリ)
/settings set key:admin-role role:(運営ロール)
/settings set key:log-channel channel:(ログ出力用テキストチャンネル)
/settings set key:recruit-channel channel:(募集メッセージを投稿する公開チャンネル)
```

| キー | 何を指定するか |
| --- | --- |
| `event-category` | イベント用チャンネルを自動作成するカテゴリ |
| `archive-category` | 終了したイベントの移動先カテゴリ |
| `admin-role` | 運営権限を持たせるロール |
| `log-channel` | 削除操作などの監査ログを出すチャンネル(閲覧権限は運営が別途設定) |
| `recruit-channel` | 参加ボタン付きの募集メッセージを投稿する、誰でも見られるチャンネル |

設定内容は `/settings show` でいつでも確認できます。

> **反映タイミングについて**
> コマンドは通常グローバル登録のため、Bot導入直後は最大1時間ほど反映が遅れることがあります。開発・検証中に即時反映させたい場合は `.env` の `DEVELOPMENT_GUILD_ID` にサーバーIDを設定してください。

## 3. イベントを作る

イベントはサーバーメンバーなら誰でも作成でき、作成した人が**幹事**になります。

```
/event create name:忘年会 area:渋谷 date:2026-12-20
```

| オプション | 必須 | 説明 |
| --- | --- | --- |
| `name` | ○ | イベント名 |
| `area` | ○ | 開催エリア |
| `date` | - | 開催日(`YYYY-MM-DD`形式)。省略可 |

実行すると自動的に:

1. `第n回参加者` ロールが作られる
2. `第n回-イベント名` という非公開チャンネルが `event-category` 配下に作られる(このロールを持つ人と運営だけが見られる)
3. `recruit-channel` に参加ボタン付きの募集メッセージが投稿される
4. 幹事自身は自動で参加登録される

「第n回」の番号はサーバー全体の通し番号です。途中でイベントを削除しても欠番になるだけで、他のイベント番号は変わりません。

---

## 4. イベントに参加する・キャンセルする

### 参加する

`recruit-channel` に投稿された募集メッセージの **「参加」ボタン** を押すだけです。
押すとロールが付与され、そのイベント専用チャンネルが見られるようになります。締切はないので、アーカイブされるまでいつでも参加できます。

### 参加をキャンセルする

イベントチャンネル内にある **「離脱」ボタン** を押すと、参加登録が取り消されロールも外れます(チャンネルが見えなくなります)。

> 幹事本人は進行管理のため、自分のイベントから離脱することはできません。イベント自体をやめたい場合は運営に `/event delete` を依頼してください。
> また、アーカイブ済みのイベントは参加・離脱どちらもできません。

---

## 5. イベント情報を編集する(幹事・運営)

イベント名やエリア、日付を変更したいときは、**そのイベントのチャンネル内で**実行します。

```
/event edit name:新年会 date:2026-01-10
```

`name` / `area` / `date` のうち、変更したい項目だけ指定すればOKです(1つ以上必須)。

---

## 6. 飲み会(お店)を記録する(幹事・運営)

イベント当日、行ったお店ごとに記録を残せます。**イベントチャンネル内**で実行してください。

```
/party add shop:居酒屋いろは amount:32000 note:予約席
```

| オプション | 必須 | 説明 |
| --- | --- | --- |
| `shop` | ○ | 店名 |
| `order` | - | 何軒目か。省略すると自動で連番になる |
| `amount` | - | 会計金額 |
| `note` | - | メモ |

登録した一覧は `/party list` で確認できます。1つのイベントに1軒目・2軒目…と複数登録可能です。

---

## 7. 会費の受領を記録する(幹事・運営)

割り勘の**計算はBotでは行いません**。「誰からいくら受け取ったか」を記録するだけの機能です。金額の割り振りは幹事が別途決めてください。

```
/payment add party:1 payer:@田中 amount:5000
```

| オプション | 必須 | 説明 |
| --- | --- | --- |
| `party` | ○ | どのお店(何軒目)に対する支払いか |
| `payer` | ○ | 支払った参加者 |
| `amount` | ○ | 受け取った金額 |

確認は `/payment list` です。`party` を指定すればそのお店だけ、省略すれば全店舗の受領記録と合計を表示します。

`payer` に指定できるのはイベントの参加者だけです。参加をキャンセルした人・削除した人の受領記録は残りますが、一覧と合計には含まれません(再参加すると元に戻ります)。

### Discord を使っていない人(ゲスト)の分を記録する

Discord を持っていない人やサーバーに参加していない人は、**ゲスト**として登録すると出席人数と会計に含められます。ゲスト本人は何も操作しません。幹事・運営が代わりに登録します。

```
/event add-guest name:山田
/event remove-guest name:山田
```

- ゲスト名はイベント内で重複できません。表示は「山田 (ゲスト)」になります。
- ゲストの出欠・受領金額は **Web コンソールのイベント詳細** で記録します(`/payment add` と `/attendance set` はゲストに対応していません)。名前の変更も Web から行えます。
- ゲストを削除しても出欠・受領記録は残ります。同じ名前で追加し直すと記録ごと元に戻ります。
- **まとめ払いの記録方法:** メンバーがゲストの分もまとめて払った場合は、支払った人の受領金額に合算額を入力し、ゲストは出席だけ付けてください。

---

## 8. イベントを終わらせる

### アーカイブ化(記録として残す)

飲み会が無事終わったら、**そのイベントのチャンネル内**で以下を実行します。

```
/event archive
```

- チャンネルが `archive-category` に移動します
- 新規メッセージの書き込みはできなくなります(閲覧のみ)
- 当時参加していた人だけが履歴を見られます
- 募集メッセージの参加ボタンは無効化され、以後は参加もキャンセルもできません

### 削除(開催中止など)

開催そのものが中止になった場合は、**運営が**イベントチャンネル内で以下を実行します。

```
/event delete
```

確認ダイアログが表示されるので、「削除する」を押すと実行されます。**この操作は取り消せません。** チャンネル・ロール・記録データがすべて削除され、誰が・いつ削除したかが `log-channel` に記録されます。

---

## 9. 「第n回」の番号を修正する(運営のみ)

同時に複数イベントが作成された直後に削除が重なるなどして番号がずれてしまった場合、運営が手動で修正できます。**該当イベントのチャンネル内**で実行してください。

```
/event renumber number:5
```

---

## 10. Webコンソールを使う

Discord上の操作に加えて、ブラウザからも確認・操作ができます。

1. 運営から案内されたURL(`PUBLIC_BASE_URL` で設定された公開URL)にアクセス
2. 「Discordでログイン」からOAuth2認証を行う
3. 所属していてBotが導入済みのサーバーが表示されるので選択(1つしかない場合は自動で遷移)

見える・できる範囲は役割によって異なります。

| できること | 参加者 | 幹事 | 運営 |
| --- | --- | --- | --- |
| 募集中イベントの一覧閲覧 | ○ | ○ | ○ |
| 過去に参加したアーカイブ済みイベントの閲覧 | ○ | ○ | ○ |
| 自分の参加履歴・支払記録の閲覧 | ○ | ○ | ○ |
| 自分が幹事のイベントの参加者・会計管理 | - | ○ | ○ |
| 全イベントの閲覧・管理 | - | - | ○ |
| Bot設定画面 | - | - | ○ |

WebとDiscordは同じデータ・同じ処理を共有しているため、Web側で編集した内容もDiscordのチャンネルや募集メッセージに即座に反映されます。逆に、Discord側でロールを変更すればWeb側の権限も次のアクセス時にすぐ反映されます。

## 11. コマンド早見表

| コマンド | 実行場所 | 実行者 | 内容 |
| --- | --- | --- | --- |
| `/settings set` | どこでも | 運営 | Bot設定の登録・変更 |
| `/settings show` | どこでも | 運営 | 現在の設定を表示 |
| `/event create` | どこでも | 全員 | イベント作成 |
| `/event edit` | イベントch内 | 幹事/運営 | イベント情報の編集 |
| `/event archive` | イベントch内 | 幹事/運営 | イベントをアーカイブ化 |
| `/event delete` | イベントch内 | 運営 | イベントを削除(確認あり) |
| `/event renumber` | イベントch内 | 運営 | 「第n回」の番号を修正 |
| `/party add` | イベントch内 | 幹事/運営 | お店を登録 |
| `/party list` | イベントch内 | 全員 | お店一覧を表示 |
| `/payment add` | イベントch内 | 幹事/運営 | 受領金額を記録 |
| `/event add-guest` | イベントch内 | 幹事/運営 | ゲストを追加 |
| `/event remove-guest` | イベントch内 | 幹事/運営 | ゲストを削除 |
| `/payment list` | イベントch内 | 幹事/運営 | 受領記録・合計を表示 |

コマンドの応答は基本的に**実行者にしか見えません**(ephemeral)。募集メッセージなど、全員に見せる通知だけ通常メッセージとして投稿されます。

## 12. よくあるつまずきポイント

- **`/event create` が「初期設定が未完了です」と拒否される** → 運営が §2 の5項目をすべて `/settings set` で設定する必要があります。`/settings show` で不足項目を確認してください。
- **`/event edit` などが実行できない** → そのコマンドは対象イベントの**チャンネル内**で実行する必要があります。募集チャンネルや別のチャンネルでは実行できません。
- **参加ボタンを押しても反応がない/参加できない** → イベントがすでにアーカイブ済みか削除済みの可能性があります。
- **幹事なのに離脱ボタンが使えない** → 仕様上、幹事は自分のイベントから離脱できません。開催自体をやめたい場合は運営に削除を依頼してください。
- **コマンドが表示されない/反映されない** → グローバルコマンドの反映には最大1時間程度かかることがあります。開発中は `DEVELOPMENT_GUILD_ID` の設定で即時反映できます。
